Agents write text. The engine renders the video.

A single Go binary that turns a short, indentation-based script into an explainer video. Built first for code-review videos: the problem, the fix, how data moves, and proof. The binary contains everything it needs, the video encoder included.

Pipeline

.reel→parse→scene graph→layout→timeline→raster→encode
  • Parse. Line-based, indentation for nesting. Every error carries a line number and a suggested fix, because agents read them.
  • Scene graph. Components from the theme pack expand into primitives here. After this step the engine only knows about primitives.
  • Layout. A flex and grid subset sizes and places everything, then connectors are routed between laid-out boxes.
  • Timeline. Verbs like draw and focus compile into property tracks. A frame is a pure function of time.
  • Raster and encode. Frames render in parallel on all cores, and unchanged frames are reused. Raw pixels are piped to an encoder.

Script format

One file per video. The shape is meant to be easy for a model to write correctly on the first try: few symbols, no closing tags, no quoting except for visible text.

video "PR 482 · cache refresh"
  theme hairline
  size 1920x1080  fps 30

style
  process          enter=fade
  .hot             state=focus
  #api process.idle  state=dim

scene establish 3s
  row gap=240 align=center
    laptop #web "laptop · web"   enter=none
    server #api "server · api-1"  enter=fade
  say "A client and ==one server=="

scene request
  #web -> #api "GET /v1/items" for=1.5s   # arrow draws by default
  focus #api/unit1 at=2s
  say "The request travels to the server"

scene inside
  camera zoom #api for=0.8s
  #api/procs
    process #p1 .hot  "api"    note="2 in flight"
    process #p2       "cache"  note="running"
    process #p3 .idle "worker" note="idle"
  say "Zoom in: ==one process holds both requests=="

scene proof
  camera reset
  row gap=120
    use #api scale=0.6
    terminal #t
      $ curl -i api.internal/v1/items
      HTTP/1.1 200 OK
      x-load: ==shared==
  #api ..> #t "stdout"
  type #t
  say "Both callers got one shared load"

scene fix
  diff cache.go hunk=1 focus=+12..+14
  say "singleflight collapses concurrent refreshes"

Rules

  • A line is kind #id .class "text" key=value …. Only kind is required. Indented lines are children.
  • Connectors are their own lines: a -> b arrow, a -| b elbow, a ~> b curve, a ..> b dashed, a <-> b both ways, a -- b plain line.
  • Inline text marks: ==bright== for emphasis, __text__ for underline, `code` for mono.
  • Parts of a component are addressed with a slash: #api/unit1, #api/procs. The dot is kept for classes.
  • Steps in a scene run in order. with runs a step at the same time as the previous one; wait 0.5s pauses. Exact timing is covered under Motion and timing.
  • Elements persist into the next scene unless the scene starts with clear, so a story can build up and the camera can move through it.

Selectors and the cascade

Selectors work everywhere an element is named: in style rules, in steps (dim process:not(.hot)), in connectors (#web -> #api/unit1) and in the camera (camera zoom .hot).

#a, #beither

What the cascade does

Several rules can set the same property on the same element. The theme says processes fade in, a style rule says .hot processes are focused, and the element line itself may say state=rest. The cascade is the fixed order that decides which one wins, so the result never depends on luck.

  1. Theme defaults for the kind.
  2. Theme style rules.
  3. The script's style block. A more specific selector beats a less specific one (id over class over kind), and on a tie the later rule wins.
  4. Properties written on the element's own line.
  5. Steps during playback, such as focus #p1. These last until another step changes them or the scene ends, depending on the verb.

A few properties inherit from the parent container unless set: font, text color and enter mode. There is no !important. reel check --explain #p1 prints every property on an element and the rule that set it, so an agent can debug a style without guessing.

Layout

A small subset of CSS flexbox and grid, enough to place a handful of things well. No cascade, no selectors.

  • row and col are flex containers: gap, align, justify, pad, wrap.
  • grid cols=3 with gap; children flow into cells, span=2 to widen.
  • layer stacks children on top of each other; place x= y= is the escape hatch for absolute positions.
  • Sizes: px, %, fr, auto. Text is measured with real font metrics, so auto fits labels exactly.
  • Connectors are routed after layout. Aligned ends get a straight line; others get one or two right angles, never a diagonal.
  • The root is the safe area of the frame, with title and caption bands reserved by the theme.

Motion and timing

Entering and exiting

Drawing is one option, not the rule. Each element has an enter and an exit mode. The theme sets defaults per kind and the script can override either, through a style rule or on the element's line.

ModeAs enterAs exitHairline default for
drawStrokes trace in, then fills fade inFills fade, then strokes untraceconnectors, diagram shapes, chart lines
fadeOpacity 0 → 1Opacity 1 → 0components, text
riseFades in moving upFades out moving downtitles, captions
typeCharacters appear in orderCharacters erase from the endterminal commands
nonePresent at onceGone at oncecarried-over elements

When exits happen:

  • leave #x as a step, at any point in a scene.
  • clear at the start of a scene exits everything left from the previous one; clear keep=#api keeps some.
  • Elements that are still on screen when the video ends simply stay.

Groups and components can stagger=0.08s their children, so a server's units enter one after another and leave in reverse.

Steps

  • State changes: focus, dim, active, select, trace, rest. Focusing one element can dim its siblings (theme setting).
  • Travel: send #a -> #b moves a packet dot along a connector.
  • Camera: camera zoom #x fits the frame to an element's box; camera pan, camera reset.
  • Exits: leave #x uses the element's exit mode; leave #x exit=fade overrides it once.

Timing

Timing is automatic by default and exact when you ask for it.

WriteEffect
scene fix 6sThe scene lasts exactly 6 seconds.
draw #a for=1.5sThis step takes 1.5 seconds instead of the theme's duration.
focus #b at=2sStarts 2 seconds into the scene, whatever ran before it.
focus #c at=+0.5sStarts half a second after the previous step starts.
with type #tStarts together with the previous step.
wait 1sHolds before the next step.
hold 2sHolds at the end of the scene.
ease=…Overrides the theme's easing for one step.

Without these, steps use the theme's durations and a scene lasts as long as its steps or its caption's reading time, whichever is longer. Explicit times always win. If they don't fit, for example steps running past a fixed scene length, reel check reports it with the line number rather than silently cutting the scene.

Theme packs

A theme is a folder. Copy one, change tokens or redraw components, and every script renders in the new look.

themes/hairline/
  theme.toml          # tokens, fonts, motion, defaults
  components/
    laptop.reel       # built from primitives
    server.reel
    terminal.reel
  fonts/              # optional, bundled
[color]
bg = "#08090A"   ink = "#EDEDEF"   hi = "#F4F5F7"
line0 = "#34373F" line1 = "#6A6E7A" line2 = "#D4D7DE"

[stroke]
width = 1.2   radius = 8

[type]
sans = "Inter"   mono = "JetBrains Mono"   title = 54   caption = 20

[motion]
draw = "0.6s ease-in-out"   fade = "0.3s ease"   camera = "0.6s cubic(.2,.7,.2,1)"

[enter]
connector = "draw"   component = "fade"   text = "fade"   title = "rise"

[states]
focus = { stroke = "line2", fill = "hi/4%" }   dim = { opacity = 0.35 }

A theme can start with extends = "hairline" and override only what changes. The engine never hardcodes a color or a duration; it only reads tokens.

Extending the language

Four levels, from cheapest to deepest. Most needs stop at the first two.

  1. Styles. Classes and style rules change how existing things look and move, in the script or in a theme.
  2. Components. Composition works like React: small pieces combine into bigger ones, and a bigger one is used exactly like a primitive. See Composition below.
  3. Themes. New tokens, redrawn components and new motion defaults, with extends to inherit the rest.
  4. Engine plugins. Truly new behavior, such as a new content block (a flame graph, a Kubernetes topology) or a new verb, is written in Go against a small interface: parse its own props, lay itself out, draw to the display list. It registers a kind name and shows up in reel ref.

Unknown kinds, properties or selectors that match nothing are errors from reel check, with the closest valid name suggested. That keeps the language open to extension without letting typos pass silently.

Composition

A define block makes a new kind. The same idea as a React component, mapped onto this language:

ReactHere
propsparameters with defaults: define queue items=3 label="", used as {label}
childrenslot marks where the caller's indented lines go; named slots with slot side
components inside componentsa definition can use any other definition, primitive or built-in component
conditionals and listsif and repeat inside a definition
encapsulationinner ids are scoped: #q/slot from outside, plain #slot inside
importsimport "parts/queue.reel", or put it in a theme pack
define queue items=3 label="" enter=fade stagger=0.08s
  col gap=8
    repeat items
      box #slot w=120 h=32
    label "{label}"

define service name="api"
  row gap=80 align=center
    server #host "server · {name}"
      slot                       # caller's processes go here
    queue #jobs items=4 label="jobs"
  #host -> #jobs "enqueue"

# use it like any built-in
service #billing name="billing"
  process "api" .hot
  process "worker"
focus #billing/jobs/slot:nth(2)

Steps compose the same way. A sequence is a named set of steps with parameters, so a common move is written once:

sequence request from to text="GET"
  {from} -> {to} "{text}"
  send {from} -> {to}
  focus {to}

# in a scene
request #web #api text="GET /v1/items"

A definition can carry its own enter, exit, stagger and style rules. Callers can still override them through the cascade, the same way they override built-ins.

Renderer and speed

Decided after M0: Go for the whole pipeline, rasterizing with the pure-Go tdewolff/canvas library behind a small backend interface. Everything ships in one binary, the video encoder included.

M0 results

The four storyboard shots, 12 seconds at 1920×1080 and 30 fps (360 frames), on an Apple M5 with 10 cores. Both backends produced visually identical frames.

Backend1 core, median10 cores+ encode (x264 veryfast)
canvas, pure Go2.4 ms/frame~1,900 fps, 64× real time1.0 s total, 12× real time
resvg via cgo7.1 ms/frame194 fps, 6.5× real time1.9 s total, 6× real time

Building the display list costs about 0.02 ms per frame. With the pure-Go rasterizer, the encoder is now the slow part, so encoder choice matters more than drawing speed. These encode timings used ffmpeg only as a stand-in.

  • No headless browser. Screenshotting a browser per frame is what makes HTML-based video tools slow and heavy. We own layout and drawing instead.
  • Encoding, built in. No ffmpeg at run time. x264 is statically linked through cgo, and reel writes the MP4 container itself in Go. Defaults to a fast preset with x264's animation tuning, which suits flat frames, thin lines and text. The encoder sits behind an interface so other encoders can be added later.
  • Licence. GPL-2.0-or-later, to match x264.
  • Aspect ratios. 16:9 and 9:16 from the same script: size 1080x1920, with themes able to set different safe areas and type sizes per orientation.
  • Parallel and cached. Frames are independent, so they render across all cores. Holds and unchanged regions reuse earlier frames, which matters because explainers spend most of their time still.
  • Syntax highlighting. Chroma (Go) with a hairline style. Pierre's diff view is a JavaScript library, so it only fits a browser renderer; we match its look in the theme instead.
  • Mermaid. Mermaid itself needs JavaScript. We parse the flowchart and sequence subset ourselves and lay it out with a layered graph algorithm, which also lets the diagram use our primitives and animations.

Target: stay well above real time at 1080p30 once layout, text shaping of code blocks and the built-in encoder are in. M0 leaves a lot of headroom for that.

Agent skill

A skill file that teaches the format and the workflow. For a code review the agent:

  1. Reads the PR diff and picks one story: the problem, the change, how data moves, the proof.
  2. Writes 4 to 7 scenes, each with one focus and one caption.
  3. Runs reel check --json and fixes what it reports.
  4. Runs reel still on a few moments if it can view images, then reel render.

House rules in the skill: one emphasized phrase per caption, at most about six elements per scene, prefer components over raw shapes, and use the camera rather than cramming.

Open questions

Settled: the CLI is reel with .reel files; voiceover comes later; 16:9 and 9:16 are both supported; reel is open source under GPL-2.0-or-later with x264 linked into the single binary. A hosted service can stay closed as long as it runs reel on its own servers and doesn't hand out the binary.

  • H.264 patent licensing for how reel and the hosted service are distributed. Worth a check with a lawyer before a commercial launch.
